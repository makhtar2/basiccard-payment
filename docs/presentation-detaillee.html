Contexte général

Paiement électronique

Dans un système de paiement, une carte représente un moyen simple de stocker une valeur et d'autoriser des transactions sécurisées.

Gestion des montants

Le projet manipule des montants entiers dans une devise configurée (ici, le CFA). Pas de centimes pour simplifier la logique.

Question principale

Comment simuler un paiement par carte à puce, en protégeant l'accès avec un code PIN et en gérant un solde stocké directement sur la carte ?

Stocker

La carte garde le solde même après une opération via l'EEPROM.

Vérifier

Application Protocol Data Unit (APDU)

Qu'est-ce qu'un APDU ?

L'APDU est l'unité de communication standard entre un terminal (lecteur) et une carte à puce (ISO/IEC 7816-4).

C'est un protocole de type Maître-Esclave : le terminal envoie une Commande et la carte répond par une Réponse.

Cycle de vie

  1. Le terminal formate une commande.
  2. La carte traite l'instruction.
  3. La carte renvoie des données (optionnel) et un Status Word (obligatoire).

Structure d'une Commande APDU

CLAClasse (80)
INSInstruction
P1Param 1
P2Param 2
Lc / Data / LeDonnées transmises

Protocole : Codes retour APDU

Le protocole utilise la classe 80. Chaque réponse se termine par un code d'état (SW1SW2) indiquant le succès ou l'échec de l'opération.

CodeSignification
9000Opération réussie
6B01Solde insuffisant
6B02Montant invalide
6B03PIN incorrect
6B04Carte bloquée (3 erreurs)
Présentation Détaillée10

Protocole : Commandes (1/2)

Consultation du solde

  • CLA : 80 | INS : 10
  • Entrée : PinSaisi As Long
  • Sortie : Solde As Long

La carte renvoie le solde uniquement si le PIN est correct.

Débit (Paiement)

  • CLA : 80 | INS : 20
  • Entrée : Pin, Montant
  • Sortie : NouveauSolde

Refus si PIN incorrect, montant négatif ou solde insuffisant.

Présentation Détaillée11

Protocole : Commandes (2/2)

Crédit (Rechargement)

  • CLA : 80 | INS : 30
  • Entrée : Pin, Montant
  • Sortie : NouveauSolde

Ajoute le montant si le PIN est correct et le montant strictement positif.

Logique de blocage

Chaque mauvais PIN augmente le compteur PinErrors. À la 3ème erreur, CarteBloquee passe à 1.

Note : Un PIN correct remet le compteur à zéro.

Étape 1 : Programmer la carte

Implémentation

Le code source définit comment la carte réagit aux commandes INS reçues du terminal.

  • Lecture/Écriture sécurisée EEPROM
  • Calcul du nouveau solde
  • Émission des codes SW1SW2
' Exemple de structure
Case &H20 ' Commande DEBIT
  If Pin <> PinCode Then
    SW1SW2 = &H6B03 : Exit
  End If
  Solde = Solde - Montant
  SW1SW2 = &H9000

Étape 2 : Définir les commandes

La définition des commandes passe par la structure Command Part dans le terminal et Command Process dans la carte.

80 10Solde
80 20Débit
80 30Crédit
L'utilisation du type Long (4 octets) permet de gérer des montants jusqu'à 2 milliards de FCFA.
Présentation Détaillée15

Étape 3 : Vérifier le PIN

Algorithme de contrôle

  1. Réception du PIN
  2. Comparaison immédiate
  3. Incrémentation compteur si échec
  4. Remise à zéro si succès

Code d'erreur : 6B03

Indique spécifiquement au terminal que le PIN est erroné, permettant d'afficher un message adapté à l'utilisateur.

Présentation Détaillée16

Étape 4 : Bloquer après 3 erreurs

Sécurité Anti-Brute-Force

Une fois bloquée, la carte ne peut plus être débloquée par l'utilisateur simple.

Toute commande protégée renverra systématiquement 6B04.

' Logique de blocage
PinErrors = PinErrors + 1
If PinErrors >= 3 Then
    CarteBloquee = 1
    SW1SW2 = &H6B04
End If

Étape 5 : Effectuer un paiement

Vérifications préalables

  • Montant <= SoldeCompte ?
  • Montant > 0 ?
  • Carte non bloquée ?
If Montant > SoldeCompte Then
    SW1SW2 = &H6B01 ' Insuffisant
    Exit
End If
' Retrait effectif
SoldeCompte = SoldeCompte - Montant

Étape 6 : Recharger la carte

Processus de Crédit

L'opération ajoute une valeur au solde EEPROM. Cette fonction simule un rechargement en borne ou en agence.

If Montant <= 0 Then
    SW1SW2 = &H6B02 ' Invalide
    Exit
End If
' Ajout effectif
SoldeCompte = SoldeCompte + Montant

Étape 8 : Connecter au simulateur

Configuration Port 201

ZCMSim écoute sur le port 201. Le terminal doit être configuré pour appeler ce "lecteur virtuel" au démarrage.

' Initialisation terminal
ComPort = 201
Call WaitForCard()
ResetCard
Le terminal attend que la carte soit "insérée" dans le simulateur avant de continuer.
